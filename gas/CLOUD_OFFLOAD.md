# クラウドオフロード セットアップガイド

PCを閉じても予約投稿が動く仕組みです。スプレッドシート＋GAS（Google Apps Script）の時間トリガーが投稿を担当します。

## 概要

- **データの権威**: Webアプリ内のSQLite（編集・生成・閲覧はすべてWebアプリ）
- **投稿実行の権威**: GASの時間トリガー（クラウド側で自走）
- **同期**: Web→GAS は即時Push、GAS→Web は5分おきPull + ack
- **アカウント単位**: 各アカウントごとに別のスプシを用意

クラウドオフロードを使わずWebアプリ単体（PC起動中のみ投稿）で運用することも引き続き可能です。

## 前提条件

- Threads APIアクセストークン（このアカウント用、Webアプリにも保存済）
- Googleアカウント（スプシとGASを置く先）
- Node.js 20以上、clasp（setup-cloud.sh が自動インストール案内）

## セットアップ手順

### 1. アカウント1つあたりの作業

このアカウントで使う Threadsアクセストークンを Webアプリの「設定 → アカウント編集」から保存しておきます（先に必須）。

### 2. setup-cloud.sh を実行

```bash
cd ~/Desktop/threads-auto-webapp
bash setup-cloud.sh
```

スクリプトは以下を対話的に進めます:
1. 環境チェック（Node.js / clasp）
2. clasp ログイン誘導
3. 専用GASプロジェクト用ディレクトリ作成
4. clasp create でスプシ＋GASプロジェクトを生成
5. appscript.gs / appsscript.json をPush
6. ブラウザで GASエディタを開いて「ウェブアプリ」デプロイ（手動）
7. 表示された Web App URL をスクリプトに貼付

### 3. Webアプリ側で初期化

Webアプリの「設定 → アカウント編集 → ☁ クラウドオフロード」セクションで:
1. **Web App URL** を貼付
2. **「Key生成」** で認証キーを作成（このキーはGAS側にも自動保存される）
3. **「①疎通テスト」** で GAS との通信確認
4. **「②GAS初期化」** で Threads アクセストークンを GAS Properties に転送（GAS側で60日リフレッシュ自動化）
5. **「クラウドオフロードを有効化」** で運用開始

## 運用

### 通常の流れ

- Webアプリで投稿を生成・編集・キュー追加
- キュー追加した瞬間にGAS側スプシへ転記される
- GASの時間トリガー（毎分起動）が予約時刻になったら投稿実行
- 5分おきにWebアプリがGASから結果を取り込み、UI上で「投稿済」になる

### Macを閉じても動く

- 一度GASに転記された予約投稿は、PCの状態に関係なく実行されます
- Macを再起動した時、起動時に自動で同期が走り、停止中の投稿結果がUIに反映されます

### 編集・キャンセル

- queued状態の投稿をWebアプリで編集すると、GAS側の本文も同期更新されます
- キャンセル（status=draftに戻す）すると、GAS側のステータスも「下書き」に戻り投稿されません
- 投稿済になった投稿はGAS側でも更新できません（既に投稿済のため）

### トークン期限

- Threads長期トークンは60日で期限切れ
- GAS側で7日おきに自動リフレッシュ（v3で実証済み）
- Webアプリのダッシュボードで残り日数とトークン状態を確認可能

### 切替

- 「☁ クラウドオフロードを無効化」する場合:
  - GAS側にqueuedが残っている場合、`transferBack`（Web側に引き戻し）または `force`（強制無効化）を選択
  - 推奨は `transferBack` — Web側 cron が引き続き処理する
- 切替中は migrationLock により Web cron も GAS トリガー側ロジックも一時停止します

## 仕組み

### スプシ列構成

| 列 | 内容 |
|---|---|
| A〜M | v3互換（グループ・本文・予約日・ステータス等） |
| **N** | **Web投稿ID（Webアプリ Post.id）** ※新規 |
| **O** | **Web取込済（"1"=ack済）** ※新規 |

行物理移動に強くするため、`Post.id` をN列に書き込み、それをキーに検索します。

### 60分ガード（二段防御）

GAS側 `processScheduledPosts` 冒頭で、同一スプシ内の直近postedから60分以内なら投稿スキップ。Webからの一括Push後の凍結事故を防ぎます。

### 二重投稿防止

`Post.executor` カラムで投稿実行の権威を分離:
- `executor="local"` → Web cron が投稿
- `executor="gas"` → GAS トリガーが投稿

Web cron のクエリは `executor: "local"` フィルタが入っているので、GAS担当の投稿は物理的に拾えません。

## トラブルシュート

### 「疎通失敗」が出る

- Web App URL が正しいか確認（`/exec` で終わる形）
- GASのデプロイで「アクセス=全員」になっているか
- 認証キー（WEBAPP_KEY）が一致しているか

### 同期されない

- アカウント編集画面で「最終同期」が更新されているか
- 「今すぐ同期」ボタンで手動同期を試す
- GAS Web App URL のブラウザでの初回認証が完了しているか

### トークン期限切れ警告

- 残り7日未満で警告表示
- GASエディタを開き「実行」→ refreshAccessToken を手動実行で即時更新可能

### 既存テスター（v3スプシ）のスプシは使える？

- 使えません。v3とこの版ではスプシ列構造（N/O列追加）と認証キー方式が異なります
- 別建てで新規にスプシを作成してください
